# ADR 0001：安全策略失败时按「拒绝」处理

- 状态：已采纳
- 日期：2026-11-02

## 背景

安全闸门由多条策略组成（白名单、边界、禁区、限速、审批）。策略代码本身也可能出错——
配置解析异常、数据结构变更、第三方依赖行为变化。问题是：**策略求值抛异常时，放行还是拒绝？**

## 决策

**拒绝（fail-closed）。** `SafetyGate._safe_evaluate()` 捕获策略异常后返回
`PolicyDecision.deny(...)`，理由写进审计；任务状态变为 `blocked`，不执行任何动作。

## 理由

1. 安全组件出故障时选择放行，等于把安全组件本身变成了攻击面——攻击者只需要让它崩溃。
2. 机器人是物理系统。一次错误的动作造成的是不可逆的设备损坏或人身伤害，而一次误拦截
   的代价只是「任务失败，人工重试」。
3. 故障的可见性：`blocked` + 明确原因 + 指标 `safety_blocked_total{policy=内部错误}`
   会立刻暴露问题，而不是让异常被静默吞掉。

## 影响

- 策略实现必须可测：任何新策略都要有单测覆盖正常/异常路径。
- 策略内不要做重 I/O（如网络请求）；配置了外部依赖的策略应在装配阶段预取。
- 运维需要能区分「因策略正确拦截」和「因策略故障拦截」——后者在 `reason` 里含
  「安全策略内部错误」，应当告警。

## 替代方案

| 方案 | 为什么没选 |
|---|---|
| fail-open（异常时放行） | 把可用性置于安全性之上，与系统目的相悖 |
| 重试策略求值 | 异常通常是确定性的（代码 bug），重试只会延迟失败 |
| 跳过故障策略、继续其余 | 等于悄悄降低安全等级，且无法向审计交代 |

## 相关联的决策

同一逻辑延伸到**安全拒绝不可重试**（`SafetyViolation.retryable = False`）：
如果安全拒绝可以被自动重试，攻击者就能用「重试直到通过」的方式试探策略边界。
